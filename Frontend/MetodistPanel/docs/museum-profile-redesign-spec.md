# Профиль музея — ТЗ senior frontend / API

21 октября 2026. Визуальное направление: созданный в этой задаче макет.

## Экран

- Две равные колонки: основная информация и изображение музея.
  Карточки равны по высоте; поле краткого описания действительно заполняет
  свободную высоту левой карточки, счётчик расположен у поля, не под пустотой.
- Изображение — широкая фотография 16:9, не логотип и не квадратная иконка.
  Состояния: нет фото, выбран новый файл, сохранённое фото, загрузка, ошибка.
  JPG/PNG/WebP до 10 МБ. Выбор кнопкой и drag-and-drop, замена и удаление.
  Превью не выдавать за сохранение: файл загружается при сохранении профиля,
  только полученный постоянный URL передаётся в профиль. Отмена очищает выбор.
- Существующее поле logo_url сохраняется как совместимое хранилище URL фото:
  не ломать старые данные. Во фронтенде и публичном отображении это фото.
- Visitor получает то же изображение в карточке, шапке и информации о музее.
  Для отсутствующего/недоступного файла — спокойное пустое состояние.
- Команда отдельной карточкой на всю ширину под формой: реальные имена,
  email, роли, отметка «Вы», загрузка, пустой список и ошибка с повтором.
- Приглашение по ID/коду в раскрываемом блоке, без постоянного длинного ID
  в основной композиции. Существующий механизм приглашения сохранить.
- Только owner/museum_admin активного музея может исключить методиста.
  Перед удалением — диалог с именем и объяснением потери доступа к этому
  музею. Свою запись, владельца и администратора исключать нельзя.
- Проверка полномочий обязательна на API, не только в кнопках. Удаление
  ограничено активным музеем и не удаляет аккаунт/работы/другие членства.
- Панель сохранения: обработка pending, запрет дублей, ошибка без потери
  введённых данных. Доступные подписи, focus, 44px цели, мобильная колонка.

## API

1. POST /api/v1/museums/profile/image (artifacts): multipart file,
   авторизация по активному контексту музея, проверка типа/размера/содержимого,
   запись в AssetStore и ответ image_url. PATCH профиля публикует URL.
2. GET /api/v1/auth/museums/members (auth): только участник активного музея;
   вернуть members и can_manage. Не полагаться на глобальную роль.
3. DELETE /api/v1/auth/museums/members/{userId}: только администратор музея,
   цель — методист этого музея, запрет self/admin/owner. Атомарная проверка
   ролей и удаление членства. Сохранённый токен исключённого больше не даёт
   доступ к музею; другие музеи пользователя сохраняются.

## Проверки

Проверить загрузку и повторное чтение фото, удаление, неверный файл, ошибку
сохранения; отображение в Visitor; список реальных сотрудников и правила
удаления, чужой музей, сам себя, администратор, отсутствие полномочий,
повтор удаления и старый токен после исключения. Проверить адаптивность,
совпадение высот карточек/рост textarea и production сборку обеих панелей.
