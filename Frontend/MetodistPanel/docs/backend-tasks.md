## BE-01. Базовый каркас backend-сервиса

### Цель

Поднять минимальный backend-каркас, на котором можно последовательно реализовывать API кабинета методиста.

### Scope

- создать backend-приложение;
- настроить конфиг окружений;
- подключить БД;
- настроить миграции;
- настроить базовую обработку ошибок;
- настроить healthcheck;
- настроить базовую авторизацию middleware;
- подготовить swagger/openapi endpoint.

### Критерии приёмки

- сервис поднимается локально и в test-окружении;
- есть endpoint `GET /health`;
- есть подключение к БД и применяются миграции;
- все API отвечают в `JSON`;
- ошибки имеют единый формат;
- есть базовая структура модулей: `auth`, `museum`, `artifacts`, `routes`, `visitors`, `dashboard`.

### Необходимые тесты

- healthcheck возвращает `200`;
- приложение стартует с валидным env;
- приложение не стартует без обязательных env;
- миграции применяются на пустую БД;
- базовый формат ошибок проверен интеграционно.

## BE-02. Auth: регистрация, логин, refresh, logout

### Цель

Поддержать экраны `Вход` и `Регистрация`.

### Scope

- `POST /api/v1/auth/register`
- `POST /api/v1/auth/login`
- `POST /api/v1/auth/refresh`
- `POST /api/v1/auth/logout`
- `GET /api/v1/auth/me`
- хеширование паролей;
- выдача `access_token` и `refresh_token`;
- endpoint `me` для session bootstrap фронтенда.

### Критерии приёмки

- пароль не хранится в открытом виде;
- регистрация возвращает созданного `user`;
- логин возвращает `access_token`, `refresh_token`, `token_type`, `expires_in`;
- refresh выдаёт новую пару токенов или новый access token по принятой стратегии;
- logout инвалидирует refresh token;
- `GET /auth/me` возвращает текущего пользователя по access token;
- закрытые endpoints недоступны без авторизации.

### Необходимые тесты

- успешная регистрация;
- регистрация с уже занятым `email`;
- успешный логин;
- логин с неверным паролем;
- refresh с валидным токеном;
- refresh с протухшим/отозванным токеном;
- logout инвалидирует refresh token;
- `me` с валидным access token;
- запрос к защищённому endpoint без токена возвращает `401`.

## BE-03. Профиль музея: получение и редактирование

### Цель

Поддержать вкладку `Профиль музея`.

### Scope

- `GET /api/v1/museum/profile`
- `PATCH /api/v1/museum/profile`
- чтение и обновление:
  - `name`
  - `shortDescription`
  - `website`
  - `foundedYear`
  - `address`
- `code` доступен только для чтения;
- валидация полей.

### Критерии приёмки

- frontend получает весь профиль музея одним запросом;
- `code` возвращается в ответе, но не меняется через `PATCH`;
- редактируемые поля сохраняются и возвращаются повторно;
- невалидный `website` или `foundedYear` отклоняются с понятной ошибкой;
- редактирование доступно только авторизованному пользователю музея.

### Необходимые тесты

- успешное получение профиля;
- успешное обновление разрешённых полей;
- попытка изменить `code` игнорируется или возвращает validation error;
- валидация `website`;
- валидация `foundedYear`;
- доступ без авторизации — `401`.

## BE-04. Загрузка логотипа музея

### Цель

Поддержать блок `Логотип музея`.

### Scope

- `POST /api/v1/museum/logo`
- загрузка файла в storage;
- сохранение `logoUrl` в профиле музея;
- валидация формата и размера.

### Критерии приёмки

- принимаются только разрешённые форматы;
- после успешной загрузки профиль музея возвращает новый `logoUrl`;
- старый логотип либо заменяется, либо архивируется согласно стратегии;
- недопустимые файлы не сохраняются.

### Необходимые тесты

- успешная загрузка PNG/JPG;
- отказ для неразрешённого MIME type;
- отказ для слишком большого файла;
- после загрузки `GET /museum/profile` возвращает новый `logoUrl`.

## BE-12. Контент артефакта: выдача экранов

### Цель

Поддержать шаг `Контент` в правильном виде: сначала только стартовый и финальный экран.

### Scope

- `GET /api/v1/artifacts/{artifactId}/screens`
- генерация или инициализация системных экранов;
- гарантированный порядок экранов.

### Критерии приёмки

- для нового артефакта API возвращает только:
  - `system-start`
  - `system-finish`
- оба системных экрана нельзя удалить;
- пользовательские экраны, если есть, всегда находятся между системными.

### Необходимые тесты

- новый артефакт возвращает 2 системных экрана;
- системные экраны стоят первым и последним;
- отсутствие пользовательских экранов не ломает ответ.

## Definition of Done для backend-задач

Каждая задача считается завершённой, если:

- код реализован;
- миграции добавлены;
- openapi/contract обновлён;
- unit/integration тесты написаны;
- happy-path и negative-path покрыты;
- ручка ограничена текущим музеем пользователя;
- code review пройден;
- локально и в CI тесты зелёные.
