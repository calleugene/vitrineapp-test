# Редактор контента экспоната

## Цель
Методист собирает историю из текста с фото, тестов и 3D-моделей. Каждый формат создаётся, редактируется, сохраняется и отображается в Visitor. Сохранение черновика не публикует изменения.

## UI и взаимодействия
- Сохранить навигацию кабинета, светлые карточки, тонкие границы и жёлтую основную кнопку.
- Рабочая область: список экранов слева, редактор в центре, портретный предпросмотр справа. На небольшом ноутбуке предпросмотр переносится ниже; на телефоне блоки располагаются в одну колонку.
- В выборе типа — три полноразмерные кнопки с иконкой, названием и коротким объяснением: «Текст и фото», «3D-модель», «Тест». Убрать заглушки «в следующем обновлении».
- В списке: номер, тип, заголовок, миниатюра. Выбранный экран выделен. Порядок меняется перетаскиванием и доступными с клавиатуры кнопками вверх/вниз. Дублирование и удаление доступны через меню.
- Текст: заголовок, описание, необязательная фотография с предпросмотром и удалением. JPEG/PNG/WebP до 10 МБ.
- Тест: вопрос, 2–6 непустых уникальных вариантов, один правильный ответ, необязательное пояснение и фото. Отметка правильного ответа радиокнопкой. В предпросмотре можно ответить и сбросить попытку.
- 3D: заголовок, описание, загрузка автономного GLB до 50 МБ, интерактивное вращение/масштабирование. Внешние зависимости модели запрещены: файл должен содержать ресурсы внутри себя. Допускается существующий безопасный URL модели. Показать состояния загрузки и ошибки.
- Изменения полей отражаются в предпросмотре сразу. Сохранение — явно кнопкой «Сохранить экран», с состоянием ожидания и результатом. При ошибке введённые данные остаются.
- Защищать несохранённый экран при выборе другого, добавлении, уходе из раздела, закрытии вкладки. Не допускать повторного сохранения и действий во время загрузки.
- Подписи связаны с полями, ошибки озвучиваются, управление работает клавиатурой, фокус виден. Все действия доступны без drag-and-drop.

## Контракт
- Существующие API экранов принимают type=text|quiz|model. Payload version=1, объект content.
- Общие поля content: body, image_url. Тест: options (строки), correct_answer (строка из options), explanation. Модель: model_url.
- Частично заполненный новый экран допустим как черновик. Публикация проверяет готовность теста/модели и возвращает screen_content_incomplete для незаполненного контента.
- POST /api/v1/artifacts/{artifactId}/screens/{screenId}/model — multipart file; ответ model_url. Проверить принадлежность экспоната и экрана музею, тип model, размер, GLB 2.0 и встроенность ресурсов. Загрузка не меняет payload до сохранения.
- Сохранить совместимость старых текстовых payload и неизменяемые снимки публикации. Новая схема БД не требуется.
- Visitor сохраняет типы при чтении снимка, показывает модель через model-viewer, тест — с независимым состоянием каждого вопроса и пояснением после ответа. Вертикальная навигация сохраняется.

## Приёмка
Создать все три типа, изменить и повторно открыть; дублировать и переупорядочить; проверить защиту несохранённых полей. Загрузить валидный GLB, отклонить повреждённый/внешние ресурсы/чужой музей. Проверить в опубликованном снимке и Visitor несколько тестов подряд, модель, старый текст. Проверить ширины 390 и 1280 px, lint/typecheck/build, тесты API и преобразования публикации.
