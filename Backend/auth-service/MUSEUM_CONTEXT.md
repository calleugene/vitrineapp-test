# Контекст собственного музея

- `POST /api/v1/auth/register` создаёт методиста и серверный `museum_id` вместе с его учётной записью. Запрос не принимает ID музея от клиента. Регистрация посетителя не создаёт музей.
- `POST /api/v1/auth/login` и `POST /api/v1/auth/refresh` включают сохранённый `museum_id` в подписанный access token. `GET /api/v1/auth/me` возвращает его в `user`.
- Старый методист без `museum_id` может явно выбрать создание собственного музея. Панель вызывает `POST /api/v1/auth/museum-context` с его bearer token. Доступ разрешён только роли `methodist`. Ответ: `user`, `access_token`, `token_type`, `expires_in`. Refresh token и ID сессии не меняются.
- Назначение выполняется условным обновлением записи пользователя и повторяется безопасно: повторный запрос возвращает тот же `museum_id` и новый access token. Если ответ потерян, клиент повторяет запрос; при истёкшей сессии входит заново. Клиент сохраняет новый токен и пользователя только после полного успешного ответа.
- `POST /api/v1/museums/profile` в ArtifactsService создаёт профиль для ID из подписанного токена. При потерянном ответе клиент проверяет `GET /api/v1/museums/profile` и считает создание успешным только если сохранённые поля совпадают с отправленными.

Смена музея и присоединение к существующему музею требуют отдельного разрешённого сценария. Этот endpoint их не выполняет.
