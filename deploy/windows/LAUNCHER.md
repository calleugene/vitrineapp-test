# Запуск сервера

Дважды нажмите `VitrineServer.exe` в корне репозитория. Программа проверит
работоспособность стенда, запустит отсутствующие процессы и покажет адреса.
Это запускающий файл установленного стенда: рядом нужны `.runtime`, `deploy`
и собранные интерфейсы `Frontend/*/dist`. Перенос одного EXE на другой ПК
не переносит базу данных и сам сервер.

На рабочем столе доступны ярлыки **Vitrine Server** для запуска и
**Vitrine Stop** для остановки.

## Автоматическая проверка

В Планировщике заданий Windows зарегистрировано задание **Vitrine Server Health**:

- каждые 30 минут;
- при входе текущего пользователя в Windows;
- без открытого Codex и без всплывающих окон;
- на аккумуляторе тоже.

Проверяются PostgreSQL, Auth, Artifacts, Visitor, обе страницы интерфейса.
Для Auth ожидаемый ответ без токена — 401. Обнаруженный неработающий процесс
перезапускается, затем проверка дожидается готовности. Логи:
`.runtime/logs/watchdog.log` и `.runtime/logs/launcher.log`.

Проверка раз в 30 минут не предотвращает сбой: при сбое между проверками
сервер может быть недоступен до следующей проверки. При выключенном ПК,
выходе пользователя из системы или во сне проверка не выполняется;
после входа/пропущенного запуска Windows снова проверяет стенд.

## Управление из PowerShell

```powershell
./VitrineServer.exe start
./VitrineServer.exe check
./VitrineServer.exe stop
```

`stop` устанавливает режим обслуживания: последующие автоматические проверки
не запускают сервер. `start` снова разрешает восстановление.
Для тихого запуска можно передать `start --quiet`.

Повторная сборка: `./deploy/windows/Build-Launcher.ps1` (нужен Go 1.25+).
Повторная регистрация расписания: `./deploy/windows/Install-Watchdog.ps1`.
Бинарный файл и ярлыки исключены из Git; исходники находятся в
`deploy/windows/launcher`.

При изменении пути репозитория пересоздайте ярлык и повторно запустите
Install-Watchdog.ps1, чтобы Windows использовала новый путь.
