# Тестовый стенд Windows

Исходный репозиторий: https://github.com/calleugene/vitrineapp-test
Базовый commit: 8835f60740caddb85fc713b5d8e1bc53aa9a7bd1.

## Что запущено

Один веб-сервер Caddy на порту 80 раздаёт обе собранные React/Vite страницы
и направляет запросы API в Go-сервисы. Docker и WSL не требуются.

| Адрес | Назначение |
|---|---|
| http://localhost/ | Visitor |
| http://localhost/methodist/ | Кабинет методиста |
| http://192.168.31.125/ | Visitor в локальной сети |
| http://192.168.31.125/methodist/ | Методист в локальной сети |
| /api/auth/* | Auth, 127.0.0.1:18080 |
| /api/artifacts/* | Artifacts, 127.0.0.1:18081 |
| /api/visitor/* | Visitor API, 127.0.0.1:18088 |
| /media-files/* | Загруженные файлы |

PostgreSQL 16.15 слушает только 127.0.0.1:55432. Используются отдельные базы
vitrine_auth, vitrine_artifacts, vitrine_visitor. Секреты случайные и находятся
в `.runtime/config.json`; каталог `.runtime` исключён из Git.

Тестовая учётная запись методиста: `.runtime/test-account.txt`. Она привязана
к mus_001. Новые регистрации автоматически к музею не привязываются — так
устроен исходный AuthService. Тестовый музей и один опубликованный экспонат
созданы для проверки связи Methodist → PostgreSQL → Visitor.

## Управление

В PowerShell из корня репозитория:

```powershell
./deploy/windows/Start.ps1
./deploy/windows/Status.ps1
./deploy/windows/Backup.ps1
./deploy/windows/Stop.ps1
```

При обновлении: сделать Backup, остановить стенд, запустить Build.ps1, затем
Start.ps1 и Status.ps1. Повторный Start не дублирует уже работающие процессы.
Для изменения режима адреса сначала необходим Stop.

Запуск после перезагрузки ручной. При выключении или сне компьютера сайт
недоступен. Автовосстановление упавших процессов пока не настроено.
Логи находятся в `.runtime/logs`, данные PostgreSQL — в `.runtime/pgdata`,
файлы — в `.runtime/assets`. Резервные копии — в `.runtime/backups`;
для защиты от потери диска копируйте их на отдельный носитель. Делайте backup
при остановленных пользовательских изменениях для согласованности БД и файлов.

Для установки заново нужны Git, Node.js 24, Go 1.25 или новее:
Install-Runtime.ps1 → Initialize.ps1 → Build.ps1 → Start.ps1.
Initialize.ps1 запрещает перезапись существующей базы.

## Домен vitrineapp.ru

На момент проверки A-запись: 92.53.96.117, DNS обслуживает Timeweb.
DNS не изменялся. Внешний доступ и публичный HTTPS пока не настроены.

Вариант с прямым доступом:

1. Узнать белый внешний IPv4 домашнего подключения и проверить отсутствие CGNAT.
   Адрес VPN не подходит. Локальный 192.168.31.125 не подходит для A-записи.
2. Закрепить за ПК 192.168.31.125 в DHCP роутера.
3. Направить TCP 80 и 443 роутера на те же порты 192.168.31.125.
4. В Timeweb заменить A-запись корня домена на внешний IPv4.
   Проверить AAAA-запись: она не должна вести на другой сервер.
5. Остановить стенд и запустить `./deploy/windows/Start.ps1 -Public`.
   Caddy запросит сертификат для vitrineapp.ru, публичные QR-ссылки будут
   содержать https://vitrineapp.ru/exhibits/… .
6. Проверить с телефона через мобильный интернет, а не домашний Wi-Fi.

Без доступа к роутеру возможен исходящий Cloudflare Tunnel. Для постоянного
домена в стандартном варианте нужны аккаунт Cloudflare, добавление домена и
смена NS у регистратора с сохранением всех необходимых DNS-записей (включая
почтовые). Сам домен остаётся зарегистрирован в Timeweb. Tunnel направляется
на http://127.0.0.1:80; HTTPS завершается на стороне Cloudflare. В этом режиме
нужно оставить Caddy в HTTP-режиме, а ARTIFACTS_PUBLIC_BASE_URL отдельно
настроить на https://vitrineapp.ru. Настройка туннеля пока не выполнена.

Документация: https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/create-local-tunnel/
и https://caddyserver.com/docs/automatic-https .

## Ограничения исходного проекта

- В docker-compose.yml указаны отсутствующие museum-service, route-service,
  dashboard-service, analytics-service, feedback-service, notification-service.
  Их API на этом стенде возвращают явный HTTP 503.
- Visitor в auto-режиме использует демонстрационный каталог: текущий Visitor
  API не реализует `/museums`. При этом опубликованные экспонаты mus_001 и
  профиль музея действительно загружаются из Artifacts API.
- Создание/редактирование профиля музея и текстового экспоната, публикация,
  публичный просмотр, регистрация/вход и создание гостя доступны в имеющемся коде.
- Не выполнен полный аудит безопасности приложения. Это тестовый стенд.
- Для камеры/WebAR на другом устройстве требуется доверенный HTTPS;
  обычный HTTP по LAN-адресу этого не обеспечивает.

## Проверено

- Сборка обоих интерфейсов и трёх Go-сервисов.
- HTTP 200 у обеих страниц, Visitor healthz и публичного списка экспонатов.
- Регистрация методиста, привязка к музею, вход, защищённый список экспонатов.
- HTTP 401 при чтении защищённого списка без авторизации.
- Создание гостевого посетителя.
- Создание профиля музея, экспоната и текстового экрана; публикация и чтение
  опубликованного снимка через общий веб-адрес.
- В браузере открываются Visitor и экран входа методиста.

Доступ с другого физического устройства и из интернета требует отдельной проверки.
