# S-007 — Автоматическое обновление токена методиста

Основание: пользователь поручил устранить повторный вход после истечения access token. Исполнитель: frontend developer. Область: клиент API и синхронизация сессии кабинета методиста. Серверные TTL, права, схема хранения, интерфейс посетителя и главная не меняются.

## Существующий контракт

POST /api/auth/api/v1/auth/refresh, JSON {refresh_token}; ответ access_token, refresh_token, token_type, expires_in. Сервер атомарно ротирует refresh token и отзывает предыдущую сессию. Источник: Backend/auth-service/internal/auth/{handler,dto,service}.go.

## Критерии

- Авторизованный запрос с ответом 401 вызывает обновление и повторяется один раз с новым access token, сохраняя метод, тело и контекст музея. Это относится и к загрузке QR.
- Параллельные запросы используют одно обновление; поздний ответ 401 от старого токена использует уже полученные токены.
- Оба токена сохраняются в sessionStorage и синхронизируются с React; отложенное обновление профиля не возвращает прежние токены.
- Ошибки сети и 5xx сохраняют сессию для повторной попытки. Отозванный/истёкший refresh (401/403) завершает текущую сессию. Обычный 403 не вызывает обновления.
- Нет циклических попыток. Login/register/reset/legal/logout и mock-сессии не запускают обновление.
- Выход, смена аккаунта/музея во время обновления имеют приоритет: устаревший результат не сохраняется и запрос не повторяется от имени другого контекста.
- Существующие проверки и тесты новых сценариев проходят. Публикация — штатный push production.

## Не входит

Изменение срока действия токенов, хранение в localStorage/cookie, фоновый таймер, новая авторизация, изменения серверной политики, автоматическое восстановление уже удалённых сессий.
