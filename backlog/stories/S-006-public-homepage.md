# S-006 — Главная: музейные маршруты и работающие входы в продукт

- **Тип / статус:** Улучшение / Реализовано локально, проверка и публикация в рамках поручения пользователя от 2026-10-28.
- **Исполнитель:** Senior Frontend Developer в рамках поручения.
- **Ценность:** сотрудник музея понимает, что «Витрина» создаёт браузерные музейные маршруты, находит кабинет методиста и действующую форму обращения; посетитель находит свою панель.
- **Источники:** пользовательское поручение, D-001/D-002, PRODUCT.md; существующая production-ветка `calleugene/vitrineapp-test`, исходная точка `19e6b6c`, папка `Landing/`.

## Инварианты и scope

Сохраняется существующая сборка Vite/React в статические HTML/CSS/JS и музейная визуальная стилистика. Меняются только публичная главная и её сопроводительная документация. Не меняются панели `/methodist/` и `/visitor/`, API, сервер, авторизация, модель данных, workflow развёртывания и семантика публикации. Публичные draft и приватные данные не показываются. Базовый маршрут не требует native app или XR.

Существующие цены, состав тарифов, юридические документы, компонент `LeadForm`, контракт заявок `lib/leads.ts` и серверная доставка заявок сохраняются. Проверка продуктовой полноты уже опубликованных тарифных обещаний не входит в эту задачу; новые неподтверждённые возможности, тарифы, отзывы, логотипы, статистика и сроки не добавляются. Отправка заявки должна оставаться реальной и явно показывать отсутствие настроенного endpoint или ошибку.

## Предложенный порядок реализации

1. Первый экран: понятное предложение музейных маршрутов в браузере, основной CTA в существующую форму demo, второй CTA в `/visitor/`; в шапке прямой вход `/methodist/`.
2. Краткое объяснение продукта без новых неподтверждённых форматов и аналитических обещаний; три сценария: постоянная экспозиция, временная выставка, тематический маршрут.
3. Две явно обозначенные панели с реальными ссылками и кратким назначением. Существующие иллюстрации сохраняются, не выдаются за скриншоты продукта. Существующий пример истории маркируется как демонстрационный; `/visitor/` не называется опубликованным демомаршрутом.
4. Процесс: подготовка → проверка → публикация → открытие по ссылке/QR. FAQ дополняется условиями начала работы и отсутствием обязательной установки приложения/XR.
5. Кнопки ожидания, видео и несуществующих разделов заменяются действующими обращениями или ссылками. Заявки тарифов сохраняют `source`, `plan`, `billingPeriod` и поступают через существующую форму с `intent=demo`.
6. Адаптивная и функциональная проверка, штатная сборка, публикация проверенной версии и проверка доступности главной и входов панелей.

## SCREENS & STATES / USER FLOW

Главная → объяснение продукта → панель методиста/посетителя либо форма обсуждения запуска. Мобильная навигация имеет существующие состояния открыто/закрыто; Escape закрывает её и возвращает фокус. Форма сохраняет состояния idle/sending/success/error/unconfigured. Dialog использует существующий механизм управления фокусом и закрытия. Одновременно не создаются две формы с одинаковыми идентификаторами полей.

## API DEPENDENCIES

Новых API нет. Сохраняется контракт `LeadForm` → `sendLead` → настроенный `leadEndpoint` и проверка JSON `{ ok: true }`. Для ссылок используются существующие `/methodist/` и `/visitor/`; собственный публичный token маршрута не выдумывается.

## Acceptance criteria / ACCESSIBILITY / VISUAL ACCEPTANCE CRITERIA

1. Первый экран объясняет браузерные музейные маршруты; основной CTA открывает настоящую форму обсуждения запуска. Присутствуют понятные и корректные входы в обе существующие панели.
2. Есть краткое объяснение двух интерфейсов, три сценария, процесс и условия начала работы. Нет видео/социальных/разделовых кнопок, ведущих только в «готовится». Иллюстрации и демонстрационный пример не выдаются за внедрение клиента или опубликованный маршрут.
3. Новые тексты не обещают неподтверждённых результатов/возможностей. Существующие тарифные суммы и содержание сохранены; формы, контакты, юридические ссылки не сломаны. Новые трекеры и интеграции не добавлены.
4. При ширинах 320, 768, 1024, 1440 CSS px нет горизонтального переполнения, перекрытий или обрезанного содержимого; проверяется масштабирование до 200%.
5. Одна смысловая `h1`, корректный язык, последовательные заголовки, семантические ссылки и кнопки. Все элементы доступны клавиатурой, видимый focus, логичный порядок обхода. Контраст текстов WCAG AA, существующие анимации учитывают reduced motion. Содержимое не зависит от hover.
6. Проверены открытие/закрытие диалога, возврат фокуса, мобильное меню, FAQ, переключатель периода оплаты; контекст выбранного тарифа доходит до формы. Вызванных изменением ошибок консоли нет. Штатные build/lint и существующие lead tests проходят.
7. После публикации проверены HTTPS-главная, её assets и входы панелей. Успешный HTTP-ответ не приравнивается к полной проверке авторизованных сценариев.
