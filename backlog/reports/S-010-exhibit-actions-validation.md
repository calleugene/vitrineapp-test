# S-010 — Проверка действий экспоната

29 октября 2026. База production 0949851.

- Пользовательские подписи во всей панели используют «Экспонаты»; идентификаторы, URL и API не переименованы.
- Меню: Редактировать / Дублировать / Удалить / В архив; в архиве — Восстановить. Архив отдельной карточкой внизу. Загружаются все страницы API, чтобы архив не вытеснял активные экспонаты из первых 24 строк.
- Подтверждение удаления с названием и предупреждением, начальный фокус на Отмена, возврат фокуса при отмене. Ошибка остаётся в диалоге; запрос и повторное подтверждение блокируются на время удаления. Архив/копирование/восстановление также защищены от повторного запуска.
- DELETE теперь логически удаляет и черновики, и опубликованные экспонаты через deleted_at. Списки, счётчики, GET, public code, QR и вложенные действия исключают удалённые записи. Неизменяемые снимки сохраняются внутри БД. Обычное восстановление удалённого объекта недоступно. Авторизация музея и роли остаются в существующем middleware.
- Добавлена совместимая PostgreSQL-миграция nullable deleted_at. Существующие записи не меняются. PostgreSQL-адаптер и SQLite-адаптер используют одинаковые ограничения выборок.

## Ограничения

Браузерная проверка использует локальный компонент с тестовой моделью, серверные операции отдельно проверены handler/repository-тестами SQLite. Реальные экспонаты пользователя не удалялись и не архивировались. PostgreSQL локально не запускался: Docker daemon недоступен. Миграция применяется штатно при старте сервиса; доступность сервисов проверяет процесс публикации. Существующие неизменяемые снимки маршрутов не переписываются при удалении экспоната.
